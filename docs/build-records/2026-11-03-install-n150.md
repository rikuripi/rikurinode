## Evidence log

- **Attempt 1** (stick `rikuri-node-44.20261103.3.iso`, [publish run 41712055209](https://github.com/rikuripi/rikurinode/actions/runs/41712055209); the owner checked its SHA-256): the N150 started from the stick and the installer ran on its screen, then refused: two internal disks, `unknown model, 63 GB, serial 0x7c5ca232 (/dev/mmcblk0)` (built in) and `ORICO, 2048 GB, serial N380000000000001059 (/dev/nvme0n1)` (owner's photo). Nothing was erased. Fixed by `docs/build-records/2026-11-03-installer-pick-disk.md` (PR #61).
- **The stick installed** ([publish run 41727132729](https://github.com/rikuripi/rikurinode/actions/runs/41727132729), on `main` at `7950214`, all four jobs passed): `rikuri-node-44.20261103.4.iso`, SHA-256 `1347d90a5a00140199e64e25abdca80145f00ea10ba420e0e011d96ee1db655f`; it holds `ghcr.io/rikuripi/rikurinode@sha256:6d63fd6d360a2337a2105d766ef37d3ea1f7294ab3430e6d0ec4cb63e32c08df` and installs it as `ghcr.io/rikuripi/rikurinode:44.20261103.4`.
- **Attempt 2** (owner, 2026-11-03): the installer listed the two disks by number; the owner typed `2`; it named the ORICO; the owner typed `ERASE`; it showed **Installing** and then **Rikuri Node is installed. Remove the USB stick now.**
- **The stick was still in when the N150 restarted,** and its firmware started from the stick again, so the installer appeared again. The installer writes the node's own entry into the firmware (`install_argv`, no `--generic-image`), but this firmware still put the USB stick first.
- **The owner changed the boot order** to the ORICO, and nothing else in the firmware. The N150 then started **Fedora Linux 44 (IoT Edition)** and a login prompt from the ORICO. No account exists, as designed until 5c: the image and the install set no user, password or key.
- **Secure Boot** shows **Disabled** in the N150's firmware (owner, read only). The stick and the installed node started with it off.

**Proven:** the published stick starts on the N150 and runs the installer on its screen console (5a left this unproven); a disk picked by number is the disk installed; the installed node starts from that disk alone.

**Not yet proven:**
- that the node on the N150 runs the signed digest above (`bootc status` there needs a sign-in, which comes with 5c);
- greenboot's health checks and SELinux enforcing on the N150 (both proven in CI's VM only);
- the install and start with Secure Boot enabled: an owner decision, not taken in this task.

**Lessons, in the runbook in this change:**
- a stick left in starts the installer again: power off, remove it, power on; else set the boot order to the picked disk, nothing else;
- `ERASE` only in capitals (`Erase` stops);
- a memory card in a built-in reader may be listed by number (the pick-disk verifier's Minor finding 3): take cards out.
