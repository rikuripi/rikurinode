## Repair cycle 1 (of 2): Fedora 45's Podman and shadow-utils

**CI on the merged head `af9394e`** ([OS image run 41739248183](https://github.com/rikuripi/rikurinode/actions/runs/41739248183)): the build passed. The drill passed cases 1, 2b, 3, 4 and 5 (rollback works on 45), but **failed "the containers range"**: "a --userns=auto container started: False". The install test **failed all three cases**: each console ends "This USB stick is damaged or incomplete. Nothing was erased." The owner chose to diagnose (2026-11-03, "Diagnose 45 first").

**Probe `probe/f45-podman`** (a throwaway branch with its own workflow; it never merges; the rikuri-drill VM has no outbound network, so it ran on GitHub's runner). It used the real ISO's store, and repeated each step with Fedora 44's base as a control:
- [Run 1](https://github.com/rikuripi/rikurinode/actions/runs/41746793199): the stick's store holds one image (`45.20261031.0`). Podman 5.8.7 (44) lists it, the way the installer reads it. **Podman 6.1.3 (45) lists `[]`, exit 0, no error.** On 44, `--userns=auto` started.
- [Run 2](https://github.com/rikuripi/rikurinode/actions/runs/41747934629): 45 moved its defaults into `/usr/share/containers/storage.conf.d/00-vendor.conf`, and `podman info` showed **our `/etc/containers/storage.conf` ignored**. The store named by `CONTAINERS_STORAGE_CONF`, by `--storage-opt`, or by a drop-in in `/etc/containers/storage.conf.d/` was listed on 45. `--userns=auto` with an image present: `Cannot find mappings for user "containers": no subuid ranges found` and `not enough unused IDs in user namespace` (rc=125), though the line was in `/etc/subuid`.
- [Run 3](https://github.com/rikuripi/rikurinode/actions/runs/41750622879), `--userns=auto` with five `/etc/subuid` lines: on 45, every line fails (rc=125) **without a `containers` user**, and passes (rc=0) **with one** (`useradd -r -M`), our line `containers:2147483647:2147483648` included. On 44, all five pass, with or without the user. `shadow-utils-subid` 4.19.0-7.fc44 → 4.20.0-2.fc45; no `subid:` line in either `nsswitch.conf`.

**Root causes (classes):**
1. A configuration file Fedora no longer reads: Podman 6 reads its storage defaults from `storage.conf.d`, and the installer's `/etc/containers/storage.conf` goes silently unread.
2. A name the new subid library no longer accepts: shadow-utils 4.20's lookup finds no range for a name that is not a user.

**The owner's decision** (2026-11-03, "Yes, both (Recommended)"):
1. The installer names its storage file to Podman by `CONTAINERS_STORAGE_CONF`, in its own path, for `podman images`, for the install's `podman run`, and inside it for `bootc install`.
2. The image ships a sysusers entry that creates a locked system user `containers` (no password, no shell, no home). `containers-subid` is unchanged.

Scope grows by these two (`image/installer/rikuri_install.py`; `image/rootfs/usr/lib/sysusers.d/`, checked by `check_image_root.py`), with their tests and the knowledge layer.
