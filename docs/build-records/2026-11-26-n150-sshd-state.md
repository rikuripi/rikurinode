## Result

- **Observed: the N150 accepts SSH connections from the LAN** (`192.168.68.70`, port 22 `succeeded`), and **refuses 443**: its setup pages do not answer.
- **Reasoned, not observed, from GitHub's record:** the last run of **Publish the OS image** is [run 41943857557](https://github.com/rikuripi/rikurinode/actions/runs/41943857557), 2026-11-05, on `1e104fa`; nothing has been published since. So the N150 runs a release of 2026-11-05 or earlier, from before:
  - sshd off by default (#175, 2026-11-24): Fedora's base image enabled it then, as `docs/build-records/2026-11-24-sshd-off-by-default.md`'s red run showed on the real image;
  - `rikurisetup.local` (5c.2, 2026-11-10): which would explain why the name is not found;
  - and the later setup-page changes (5c.3a). Why 443 is refused and the claim screen does not stay was not read.
- **What the open port exposes:** sshd on the LAN, not the internet (the mesh router's own rules were not read). No account has a password on images the drill has checked; whether this older image holds an authorized key was not read. So a sign-in needs a key the N150 accepts; the risk is sshd itself as a listening service.
- **The N150 cannot be updated in place today:** a node is switched to a new release only when told to, by a control plane still to come (`docs/runbooks/publish-os-image.md`), and no one can sign in at it. So a fix means a new release and a reinstall, or nothing yet.
