## 0b. Spec

- [x] **Requirement (plan §4.1):** a required check failing on four boots in a row returns the node to the previous image, on any layout the installer may produce.
- [x] **Cause (greenboot-rs #218, confirmed in run 39710186883):** the trigger unit (`DefaultDependencies=no`, all its work in `ExecStop=`) is stopped at shutdown only when something orders it against the shutdown: on Anaconda's layout, its `RequiresMountsFor=/boot` ties it to `boot.mount`, which conflicts with `umount.target`; on `bootc install`'s layout `/boot` is a bind of the root with no such unit, so the unit is never stopped and the trigger never set.
- [x] **Design:** the drop-in adds `Conflicts=final.target` and `Before=final.target`, the pair ostree's own `ostree-finalize-staged.service` uses for the same reason. The trigger stays ordered `After=ostree-finalize-staged.service`, so at shutdown it is stopped first and finalize second: the trigger is set before the update is applied, as greenboot intends, and #219's case (finalize then failing) is handled by the unapplied-update check of #28. Rejected: waiting for an upstream release (greenboot 0.16.4 is the newest; no maintainer reply on #218); the drill's layout changed instead (owner's choice).
- [x] **Policy applied:** red first; the fix in its own commit; nothing silent (the trigger logs "Setting rollback trigger" when it runs).
- [x] **Flagged concerns:** on Anaconda's layout the unit is now ordered by both `boot.mount` and `final.target`; a unit's stop job runs once, so `ExecStop=` runs once. Proven in `rikuri-drill`.
