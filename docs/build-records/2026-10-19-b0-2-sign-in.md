## 0b. Spec — requirements + design, policy applied up front

- [x] **Requirements:** EXEC-03 (step-up tokens bound to method and path, single-use, burned on a wrong route); EXEC-05 (authentication fails closed: a sessions file that cannot be read whole admits nobody; no owner means every protected route is 401); EXEC-07 (one tested network-trust helper, IPv4 and IPv6 forms; a loopback source behind a proxy is never trusted: there is no proxy, the control plane terminates TLS itself); SEC-01 and SEC-02 (no credential in a log, a response or a unit file; secrets in 0600 files under a 0700 folder; `secrecy` types for the password, the code and the session id); SEC-03 (atomic writes: temporary file and rename, same mode); SEC-05 (session verification requires expiry and issuer; refusal tests and a round trip before any library upgrade); EVID-02 stays (the status report is unchanged); the threat model's T4 (credentials never reach a log) and the stage 1 slice ("the setup page's TLS (D10) and sign-in (D11)"; negative tests: "a wrong sign-in refused and rate-limited"); the design note of 2026-10-12 (`~/Security Briefing/Installingrikurinode.md`: the claim code's format, storage, limiter, expiry and transport; `Host` and `Origin` checks; the cookie flags and CSRF token; port 80 only a redirect); the review's §3.7 (the claim, the password, the session, the step-up, "never: loginless mode, JWTs in browser storage, a LAN or Tor exemption from limits, a prefix list as the gate").
- [x] **Design:**
  - **Transport.** At first start the daemon makes a certificate authority (ECDSA P-256, ten years, `rcgen`) and a server certificate signed by it (397 days; names from `RIKURI_NAMES` plus `localhost`, IP names `127.0.0.1` and `::1`), stored as DER under the state folder; the CA's PEM beside them for download. The server certificate is re-issued at start when its names changed or it expires within 30 days (its names and dates kept beside it in `server.json`, so nothing parses X.509); the CA is never re-issued (the browsers that installed it keep trusting the node), and it signs from the same parameters it was made with, so `rcgen`'s `x509-parser` feature stays out of the tree. HTTPS: `rustls` with the `ring` provider, TLS 1.3 and 1.2, HTTP/1.1 only, served by `hyper` with `tokio-rustls` (axum's own TLS example; `axum::serve` cannot do TLS). The CA's SHA-256 fingerprint is logged at start and reported by `GET /api/setup`, for the console and the setup page (D10).
  - **The plain listener** (`RIKURI_HTTP_LISTEN`, off by default; the unit sets `:80`): a second router that serves `GET /ca.crt` (`application/x-x509-ca-cert`) and answers every other request with `308` to the HTTPS name and port; it has no API route and no state. A `Host` outside the allow-list is 421 there too.
  - **Listen policy.** `listen::parse` accepts any `ip:port` now that the API is behind TLS and sign-in (B0.1's loopback-only rule was explicitly "until B0.2"); the default stays `127.0.0.1:8443`. The plain listener's default is off, so nothing answers plain HTTP unless the unit says so.
  - **State folder** (`RIKURI_STATE_DIR`, default `/var/lib/rikuri/control-plane`): created 0700; every file written 0600 by temporary file and rename. `node.json` (the instance id, 32 random bytes in hex, made once: the sessions' issuer); `ca.key.der`, `ca.crt.der`, `server.key.der`, `server.crt.der`, `server.json` (the server certificate's names and dates; the CA's PEM is made from its DER at each start, never stored); `claim.json` (argon2id hash of the code, created and expiry times, wrong tries, retired flag); `owner.json` (argon2id hash of the password, set time); `sessions.json` (per session: the SHA-256 of its id, the CSRF token, the issuer, issued and expiry times). Step-up tokens live in memory only (five minutes).
  - **The claim code:** 10 characters from `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (no 0/O, 1/I/L; about 49.6 bits), shown as `XXXX-XXXX-XX`; input is upper-cased and stripped of dashes and spaces. The daemon arms one at its first start (no `claim.json`) and logs it with its expiry (24 hours) — the console shows the journal until the banner unit of stage 1 change 5 exists; this is the one place the code is written in clear, by design (it is how the owner learns it). `rikuri-control-plane rearm-claim`, run at the console, arms a new code (refused once the node is claimed) and prints it to stdout. `POST /api/claim {code, password}` verifies the code with argon2id (the comparison is the hash's), checks the password policy, creates `owner.json`, retires the claim and opens a session. Every refusal of the code (wrong, expired, retired) is the same `401 {"error":"claim refused"}`; `GET /api/setup` says the claim's state in words for the setup page.
  - **The limiter** (one type, one instance for the claim and one for sign-in): after 5 failures the next try is refused until a growing delay has passed (1, 2, 4 … seconds, capped at 300), answered `429` with `Retry-After`; a success resets it. The claim's count is persisted and retires the code at 20; the sign-in's count is in memory and never locks the owner out for more than the cap.
  - **The owner password:** at least 12 Unicode scalar values and at most 1,024 bytes, no composition rules (the review's §3.7); argon2id with the crate's defaults (19 MiB, 2 passes, 1 lane: OWASP's current minimum). `PUT /api/owner/password` needs a session, the CSRF token and a step-up token bound to it, and revokes every other session.
  - **Sessions:** 32 random bytes in hex in the cookie `rikuri_session` (`HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=2592000`); the store keeps the SHA-256 of the id, so the file alone opens nothing; a CSRF token (32 random bytes in hex) returned by `POST /api/session` and `GET /api/session`, required as `X-CSRF-Token` on every mutation, compared in constant time. Verification requires the record's expiry to be in the future and its issuer to equal this node's instance id (port 46, adapted from JWT `exp`/`iss`); a record that fails either is dropped. `DELETE /api/session` revokes the current session.
  - **Host and Origin:** `Host` (port stripped, lower-cased) must be an IP literal or a name in the allow-list (`localhost` and `RIKURI_NAMES`), else 421; a mutating request must carry an `Origin` whose scheme is `https` and whose host passes the same rule, else 403: the browser always sends one, so an absent `Origin` on a mutation fails closed.
  - **Peer trust (port 19):** `trust::classify(IpAddr)` returns loopback, link-local, private or public for IPv4 and IPv6, IPv4-mapped addresses classified as their IPv4. The accept loop attaches the peer address to each connection; `GET /api/status` is open to a loopback peer and needs a session from any other. Every sign-in failure is logged with the peer's class, never its address with a credential.
  - **Step-up (port 13):** `POST /api/step-up {password, method, path}` (session, CSRF, the sign-in limiter) returns a token bound to the normalized action (method upper-cased; path without query or fragment, trailing slashes removed, lower-cased) for five minutes; a route that needs one reads `X-Step-Up`, consumes the token whatever happens, and accepts only the exact action; the token is also bound to the session that minted it.
  - **Request limits:** JSON bodies capped at 16 KiB; the HTTP/1.1 header read timeout 10 s; `Cache-Control: no-store` on every API response.
  - **Dependencies** (newest non-yanked on 2026-10-19, the sparse index; the probe in the Evidence log resolved them): `argon2 0.6.0` (`alloc`, `password-hash`; no `getrandom` feature, so the tree keeps one `getrandom`; the salt is 16 bytes from ring, passed to `hash_password_with_salt`), `base64ct 1.8.3` (argon2's; here it writes the CA's PEM), `hyper 1.12.0` (`http1`, `server`), `hyper-util 0.1.21` (`tokio`, `server-graceful`; the router is driven through `tower`'s `oneshot` inside a `service_fn`), `rcgen 0.14.10` (`crypto`, `ring`, `pem`), `time 0.3.55` (`std`; the certificates' dates), `rustls 0.23.46` (`ring`, `std`, `tls12`; no `aws-lc-rs`, which needs a C toolchain, and no `logging`), `rustls-pki-types 1.15.1`, `tokio-rustls 0.26.6` (`ring`, `tls12`), `secrecy 0.10.3` (`serde`), `subtle 2.6.1`, `tower 0.5.3` (`util`, now a normal dependency); random bytes and SHA-256 from `ring 0.17.14`, which rustls brings anyway (one RNG in the tree). `deny.toml` gains `ISC` to the licence allow-list (ring's `untrusted` and `rustls-webpki` carry it; ISC is permissive, functionally MIT). `Cargo.lock` holds 131 packages (66 before); `cargo tree -e normal` lists 94 crates for this target (the verifier's count; an earlier figure of 117 in this record double-counted the tree's repeated entries). The syn skip stays. `[profile.dev.package.argon2]` and `blake2` at `opt-level = 3`: argon2id at its real cost takes about a second per hash unoptimized, which made the suite take 20 s and would make the verifier's mutation run take hours; with the two hashing crates optimized the suite takes 2 s; nothing else changes.
  - **Rejected:** `axum-server` (a third crate's accept loop where axum's own example shows the hyper one); `tower-cookies` or `cookie` (one cookie, parsed and written by hand); JWTs (sessions are opaque ids with server-side revocation; the review's "never"); per-address rate limits (a LAN peer owns many addresses; the limiter is global, the design's rule); an in-memory session store (the owner would sign in after every update, and every release reboots); arming a new claim on every restart (a retired claim must stay retired until the console says otherwise); storing session ids in clear; `aws-lc-rs` (a C toolchain in CI and on the image build); HTTP/2 (`h2` and its tree, for one owner's browser); a self-signed server certificate alone (D10 chose the CA); a config file (the environment is what the unit sets, as in B0.1).
- [x] **Policy applied — first principle:** the behaviour-changing defaults, each stated here as the owner's reversible setting: sessions last 30 days; the limiter delays after 5 failures with a 300 s cap and the claim retires at 20; the claim expires after 24 hours; the server certificate lasts 397 days; the status route is open on loopback; the plain listener is off unless the unit sets it. Design rules: nothing fails silently (a sessions file that cannot be read is logged and admits nobody; a refused `Host` or `Origin` is logged with its class); runtime truth (the claim's state is read from its file on every attempt, so a console re-arm is seen at once); pinning (every direct dependency `=`-pinned, `Cargo.lock` committed). Security baseline: the trust boundary is enforced in deterministic code behind TLS; no model, no shell, no key in any log.
