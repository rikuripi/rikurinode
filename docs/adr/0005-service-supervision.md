# ADR 0005 — Service supervision: systemd enforces, the control plane decides

| | |
|---|---|
| **Status** | Accepted — owner, 2026-10-17 (the review of 2026-10-16; record `docs/build-records/2026-10-17-plan-review.md`) |
| **Decision** | §4.2 of `docs/architecture/platform-plan.md`; the form of the internal network is D14's |
| **Beside it** | ADR 0001 (Podman with Quadlet), ADR 0002 (the control plane is Rust), ADR 0003 (rootless, a range per container; under review as D13) |

## Context

The previous node ran its services under Docker Compose. Four systemd units
raced to bring the same project up (28 conflicts in five days, OWN-02);
shell wrappers were PID 1 and waited for a cookie file, so stops never
reached the daemons (14 forced kills of LND, LN-01); a root script
re-applied the kernel's `memory.high` every five minutes because Docker
reset it on each restart, and another set the OOM bias; a Rust cascade
restarted every dependant whenever bitcoind's RPC cookie rotated, and LND
restarted twice (LN-04). What kept Electrs alive was the kernel's cgroup
controls, applied around Docker by hand. The owner asked that the new node
be at least as reliable as that control plane was.

## Decision

systemd and Podman enforce; the control plane decides; the assistant only
suggests (the plan's one-page rule), made concrete:

- **One Quadlet unit per container, one target as the only bring-up path.**
  systemd's job queue is the lock; no compose project, no lock file.
- **Limits live in the unit:** `MemoryMax`, `MemoryHigh`, `MemoryLow`, CPU
  and, where the mode allows it, `OOMScoreAdjust`; the control plane sizes
  them from the hardware into one drop-in (PLAT-04), and systemd owns the
  cgroup, so nothing resets.
- **Ordering by `After=` and `Notify=healthy`:** a unit starts only once its
  dependency's health check passes. Health means function (EVID-01):
  bitcoind answers RPC, warmup included; LND's state answers, a locked
  wallet included; Tor has bootstrapped. The probes ship in the images this
  project builds (the previous node's checks used tools its images lacked,
  PLAT-06).
- **The daemon is the container's main process.** No shell wrapper; the
  unit's `StopTimeout` sits below its `TimeoutStopSec`; bitcoind and LND
  get their 90 s; stops run in the reverse of start order.
- **RPC credentials are static, one per client.** bitcoind authenticates
  LND, Electrs and the explorer with `rpcauth`: a 32-byte random password
  each, generated by the control plane at setup, its salted hash in
  `bitcoin.conf`, the password in a file (mode 0600, owned by that client's
  ID range) that LND reads through `bitcoind.rpccookie=` and Electrs through
  `--cookie-file=`. `rpcwhitelist` limits each user to the calls it needs,
  as defence in depth, not a boundary. No credential on a command line, in
  a unit file or in git; rotation is an owner action that says it restarts
  every client once. A bitcoind restart changes no credential, so no
  dependant is restarted for it; the cookie file stays inside bitcoind's
  container for its own health check. RPC, REST (Electrs 0.12 fetches blocks
  over it, unauthenticated) and ZMQ never leave the internal network (D14).
- **Restarts are bounded and judged.** `StartLimitBurst` and
  `StartLimitIntervalSec` make a crash loop a failed unit, not a hidden
  counter; `HealthOnFailure=kill` only for services that hold no funds
  (Electrs, the explorer); bitcoind and LND are restarted by the control
  plane after a diagnosis is captured (HEAL-10).
- **The control plane decides** phases (initial sync, synced, wallet locked),
  budgets, when the Electrs index build may start (after bitcoind's initial
  sync, with dbcache reduced), which repair applies, and how a release is
  applied and undone (D12). It acts through systemd and Podman, never a
  shell, and it is the assistant's only door.

## Consequences

- Not ported from the previous node: the cookie watcher and cascade, the
  compose lock, the PID-1 wrappers, the memory timer and the OOM script, the
  Electrs phase loop. Their scenarios become tests: the parallel bring-up
  race and the deadlock replay (OWN-02, OWN-03), the PID-1 stop probe under
  Podman (LN-01), one bitcoind restart with no dependant restarted (LN-04,
  re-checked on every LND and Electrs version), the Tor start order
  (PLAT-06).
- To verify on regtest before the first unit: LND 0.21.x and Electrs 0.12
  reconnect by themselves after a bitcoind restart when the credential has
  not changed (the previous node only ever saw the changed case); the exact
  `rpcwhitelist` sets, derived by observation, not guessed.
- Memory: swap on the image (zram, to verify), `MemoryHigh` backpressure
  before `MemoryMax` kills, and the index build sequenced after the initial
  sync; `OOMScoreAdjust` below the service manager's own value needs
  privilege (D13).
- A lying health check now starts services; the probes are tested red first
  (EVID-01's tripwire).

## Rejected

- Porting the cookie watcher and cascade: unnecessary once credentials do
  not rotate, and the cause of the double restarts.
- Per-service shell wrappers: systemd's ordering and `Notify=healthy` do
  what they waited for, without the PID-1 defect.
- A supervisor loop in the control plane that stops and starts containers on
  its own clock: the previous node had five actors doing that (OWN-07).
- A rotating cookie with `PartOf=` restart propagation: works, proven by the
  previous node, but every bitcoind restart would bounce LND, and every
  client would hold the one `__cookie__` identity with every RPC.
